# Testing — schoolfees app

What is unit tested, what is not, and how the app is verified when it is
released. Adapted from the Build Arsenal `TESTING_TEMPLATE` and the Flowtick
testing rules to a Vite + React + TypeScript app.

All counts below were produced by a real run on 2026-10-01. Nothing here claims
testing that was not done.

## 1. Commands

```bash
npm run lint        # oxlint
npm run typecheck   # tsc -b, strict
npm test            # vitest run
npm run build       # tsc -b && vite build
```

All four run in CI ([`.github/workflows/web.yml`](../.github/workflows/web.yml)),
on the same Node major as the maintainer's machine (24).

As of 2026-10-01: **24 test files, 154 tests, all passing** — 85 pure tests
in `node` and 69 render tests in `happy-dom`, including an axe-core
accessibility check per rendered component and page. Lint reports 0 warnings
and 0 errors across 58 files; `tsc` is clean; the production build succeeds
(with the known ~1 MB chunk warning).

## 2. What is unit tested

`vitest.config.ts` sets `environment: 'node'` and includes both
`src/**/*.test.ts` (pure functions, node) and `src/**/*.test.tsx` (render
tests, which opt into `happy-dom` with a per-file pragma). Neither kind touches
the network: page tests mock `src/lib/wallet`, and the `ContractClient` double
in `src/test/render.tsx` answers reads from fixtures and returns a fake hash.
Addresses in fixtures are generated by the real SDK's `Keypair.random()` /
`StrKey.encodeContract`, so no real or personal value ever appears in a test.

| Module | Tests | Covers |
|---|--:|---|
| `amount.test.ts` | 9 | whole-number parsing, i128-sized values, grouping, negatives, no decimal guessing |
| `contractErrors.test.ts` | 11 | the vendored `ERRORS.md` table parses to 11 variants; every variant has a mapped, identically worded message and next action; no message exists for an undocumented code; host-error parsing (`Error(Contract, #N)`); documented wording used verbatim; generic fallback; the conditional cross-repo comparison |
| `datetime.test.ts` | 7 | Unix-seconds ↔ local `datetime-local` conversion, past detection, unparseable values |
| `explorer.test.ts` | 5 | transaction and contract URLs, shortening |
| `fee.test.ts` | 11 | status order (`closed` → `paid` → `overdue` → `open`), `net`/`remaining` maths, `canClose`, `Unknown` for anything unrecognised, status descriptions |
| `network.test.ts` | 8 | the full config: testnet accepted, mainnet refused, the real-network passphrase refused even when the name says testnet, placeholder and account-shaped contract ids rejected, all four missing values reported at once, non-http URLs rejected, explorer trailing slash trimmed |
| `reference.test.ts` | 12 | exactly 64 hex characters as 32 bytes, upper-case accepted and lower-cased, wrong length, non-hex, free text and placeholders refused, **secret-key-shaped values refused**, the plain-words warning's content |
| `scval.test.ts` | 12 | JS → `xdr.ScVal` and back for address, i128, u64, 32-byte reference, and a full `Fee` record against the real SDK encoders; the symbol-encoded unit-enum status; defensive rejection of a non-fee response |
| `validation.test.ts` | 10 | account addresses (`G…`), contract addresses (`C…`), fee ids (digits, ≥ 1), and the error wording each returns |

Two things worth keeping in mind:

- The ScVal tests round-trip against the **installed SDK's real encoders**, not
  hand-written expectations, so an SDK encoding change fails the suite.
- **One test is conditional:**
  `contractErrors.test.ts` compares the vendored table against
  `../schoolfees-contracts/ERRORS.md` only when that repository is checked out
  next to this one (`it.skipIf(!existsSync(...))`). It **runs locally** (that is
  the 85th test) and is **skipped in CI**, where only this repo is present. So CI
  proves the vendored copy is internally consistent, not that it still matches
  the contract repo. Re-copying `docs/contract-errors.md` is a manual rule
  (`README.md`, `AGENTS.md`).

## 3. What is NOT tested

| Not tested | Why it matters | Tracked by |
|---|---|---|
| **Accessibility in a real browser.** Labels, landmarks, `aria-*` wiring and reduced motion are in the markup, and an automated axe-core check now runs over every rendered component and page (`src/test/render.tsx`), but no screen-reader or keyboard audit has been run and colour contrast is checked against tokens, not rendered styles. | "Built in" is not "proven"; axe is a floor, not an audit. | [draft 07](issue-drafts/07-component-and-accessibility-tests.md) |
| **Anything on-chain.** Every RPC call (`build → simulate → assemble → send → poll`), the wallet connection, the network re-check, the signature prompt, and the parsing of host error strings. | No contract is deployed and no real wallet has connected, so the entire chain-facing half of the app is unproven. | [draft 04](issue-drafts/04-end-to-end-tests-against-testnet.md); pilot gate |
| **The `status()` return encoding** of the unit-variant enum against a real contract. The app decodes defensively (symbol, single-element vec, or object) and shows `Unknown` for anything else. | A wrong decode shows `Unknown` rather than a wrong status — honest, but still unverified. | docs repo `src/todo-verify.md` |
| **Duplicate-submission behaviour under a real double click**, a slow RPC, or a second tab. The button is disabled while busy, but there is no re-entry guard and no idempotency on-chain. | A duplicate `pay` is a second real payment. | [draft 13](issue-drafts/13-guard-against-duplicate-submission.md) |
| **RPC failure modes**: a dropped connection, a slow endpoint, a rate limit, a `TRY_AGAIN_LATER`, a transaction sent but not confirmed. There is no retry and no explicit timeout. | The app reports the first failure and stops; nobody has seen how that reads on a bad connection. | [draft 11](issue-drafts/11-bound-rpc-retries-and-timeouts.md) |
| **Empty vs "no results" states, and lists.** Each page looks up one record by id, so an absent record is an error, not an empty list. Listing is not built. | Fine today; it becomes a real gap the moment a list exists. | [draft 06](issue-drafts/06-list-school-fees.md) |
| **Deep links and reload.** Navigation is `useState` tabs with no URL, so there is nothing to reload into. | Recorded as a gap, not as a covered case. | [draft 12](issue-drafts/12-url-routing-and-deep-links.md) |
| **The bundle's outbound requests.** Verified only by grepping the built assets (remote wallet icons), never by watching the network tab. | The README's "no network request other than RPC" claim was wrong once; a test would catch the next one. | [draft 15](issue-drafts/15-correct-the-outbound-request-claim.md) |
| **Performance and bundle size** beyond the build's own warning. | The initial chunk is ~1 MB. | [draft 02](issue-drafts/02-code-split-wallet-kit.md) |

**Nothing in this document claims testing that was not run.** The pre-existing
test suite was not modified by this task; the app's code was not changed at all.

## 4. Release smoke test

To be run by a human against a real deployment, once one exists (blocked by the
pilot gate). Nothing below has been run; it is written down so that "released"
means something specific. Steps that touch the chain are also in the app's
[`DEPLOYMENT_CHECKLIST.md`](DEPLOYMENT_CHECKLIST.md).

1. **Load.** Open the deployed URL with a cleared cache. The TESTNET banner is
   the first thing on screen; the console is clean; there are no failed requests
   other than the RPC calls the app intends to make.
2. **Configuration refusal.** With `VITE_CONTRACT_ID` unset or a placeholder,
   only the banner and the configuration notice render. No page is reachable.
3. **Wrong network.** Set the wallet to a non-testnet network and try an action:
   the app refuses before building a transaction, with the wrong-network
   message.
4. **Connect.** Connect a real wallet; the shortened address and the `testnet`
   badge appear; the address survives a reload.
5. **Read.** Look up a real fee id. The summary matches what the explorer shows
   for the same id, including the status.
6. **Write.** Create a fee with a synthetic reference and a small total. The
   wallet prompt names the network; after signing, the transaction hash and an
   explorer link appear; the link opens the right transaction.
7. **Failure path.** Try to overpay, or to pay a closed fee: the app shows the
   reviewed `ERRORS.md` wording and its next action, not a raw host error.
8. **Rejected signature.** Cancel the wallet prompt: the app says so, and
   nothing is submitted.
9. **Duplicate submission.** Double-click a submit button: only one transaction
   appears on-chain. (This is a check of behaviour that is currently only partly
   guarded — see draft 13.)
10. **Mobile.** Repeat steps 1 and 5–6 at 390×844: no horizontal scrolling, the
    banner visible, buttons reachable with a thumb.
11. **Keyboard.** Tab through every page: visible focus everywhere, the skip link
    works, the order matches the visual order.
12. **Reload mid-flow.** Reload after a read: the app returns to the Home tab
    (this is the routing gap, draft 12) and the wallet address is still
    remembered.

## 5. Adding a test

- Pure logic goes in `src/lib/`, with a test next to it. If it needs a browser,
  a wallet or the network, it does not belong in the unit suite.
- A bug fix gets a test that fails before the fix.
- A new error code in `ERRORS.md` means: re-copy `docs/contract-errors.md`, add
  the wording to `src/lib/contractErrors.ts`, and confirm both directions of the
  mapping test still pass — in the same commit.
- Never weaken a test to make a change pass. The refusals in `network.test.ts`
  and `reference.test.ts` are the point of those files.
